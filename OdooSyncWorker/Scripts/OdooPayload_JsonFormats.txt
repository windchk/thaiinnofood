Odoo payload JSON formats
=========================

Important
---------
JSON field names are case-sensitive.
Use the exact lowercase/camelCase field names shown in this file.
Endpoint, collection name, and docState mappings are loaded from
appsettings.json under Odoo:Routes.

Current B1 endpoint fields:
params
productions
deliverys
siteId
docEntry
docState
companyName

SalesOrder and ItemMaster sync are temporarily disabled. Their legacy fields
remain documented below only as a reference for possible future reactivation.


Disabled legacy wrapper
--------------
SalesOrder and ItemMaster previously used this wrapper but are currently disabled.
ProductionOrder and ARReserveInvoice do not use this wrapper; their exact
request bodies are documented in their sections below.

{
  "objectType": "SalesOrder | ItemMaster",
  "action": "ADD | UPDATE | CANCEL | CLOSE",
  "siteId": "TEST | PRD",
  "companyName": "TIF | STL",
  "sapDatabaseName": "TEST_INTERFACE | TEST_STL_ODOO | TIF_GOLIVE | SBO_STL_GOLIVE",
  "data": {
  }
}

Endpoint by objectType:
SalesOrder      -> disabled
ItemMaster      -> disabled
ProductionOrder -> /api/v1/b1/production
ARReserveInvoice -> /api/v1/b1/delivery

  "docDueDate": "2026-06-23T00:00:00",
  "taxDate": "2026-06-22T00:00:00",

  "canceled": "N",

    "docDate": "2026-06-22T00:00:00",
    "docDueDate": "2026-06-23T00:00:00",
    "taxDate": "2026-06-22T00:00:00",
    "docTotal": 35.096000,
    "canceled": "N",
    "lines": [
      {
        "lineNum": 0,
        "itemCode": "FG05037",
        "description": "Item description",
        "quantity": 1.000000,
        "price": 32.800000,
        "lineTotal": 32.800000,
        "whsCode": "WH-FG",
        "vatGroup": "S07"
      }
    ]

}

Source tables:
Header = ORDR
Lines  = RDR1

ActionType:
ADD    = new ORDR row
UPDATE = existing ORDR row changed
CANCEL = ORDR.CANCELED changes to 'Y'
CLOSE  = ORDR.DocStatus changes to 'C'


ItemMaster
----------

objectType:
ItemMaster

ObjectKey:
OITM.ItemCode

data format:

{
  "itemCode": "FG05037",
  "itemName": "Item name",
  "foreignName": "Foreign item name",
  "itemGroupCode": 100,
  "inventoryUom": "PCS",
  "purchaseUom": "PCS",
  "salesUom": "PCS",
  "manageBatch": "N",
  "manageSerial": "N",
  "active": "Yes",
  "createDate": "2026-06-22T00:00:00",
  "updateDate": "2026-06-27T00:00:00"
}

Full request body example:

{
  "objectType": "ItemMaster",
  "action": "UPDATE",
  "siteId": "PRD",
  "companyName": "TIF",
  "sapDatabaseName": "TIF_GOLIVE",
  "data": {
    "itemCode": "FG05037",
    "itemName": "Item name",
    "foreignName": "Foreign item name",
    "itemGroupCode": 100,
    "inventoryUom": "PCS",
    "purchaseUom": "PCS",
    "salesUom": "PCS",
    "manageBatch": "N",
    "manageSerial": "N",
    "active": "Yes",
    "createDate": "2026-06-22T00:00:00",
    "updateDate": "2026-06-27T00:00:00"
  }
}

Source table:
OITM

Active rule:
active = "Yes" when OITM.ValidFor = 'Y' and OITM.FrozenFor <> 'Y'
active = "No" otherwise

ActionType:
ADD    = new OITM row
UPDATE = existing OITM row changed


ProductionOrder
---------------

objectType:
ProductionOrder

ObjectKey:
OWOR.DocEntry

Current request body sent to /api/v1/b1/production:

{
  "params": {
    "productions": [
      {
        "siteId": "TEST",
        "docEntry": 47805,
        "docState": "release",
        "companyName": "TEST_INTERFACE"
      }
    ]
  }
}

Production docState mapping:
RELEASED -> release
CANCEL   -> cancel

Outgoing companyName:
Uses SapDatabaseName, for example TEST_INTERFACE or TIF_GOLIVE.

Source tables:
Header = OWOR
Lines  = WOR1
Item names = OITM.ItemName
Resource names = ORSC.ResName
Batch availability = OBTQ + OBTN
Batch bin availability = OBBQ + OBTN + OBIN
Bin availability without batch = OIBQ + OBIN

ProductionOrder line batch/bin:
batches:
  Available batches for the component item in that line warehouse.
  Use this when Odoo sends Issue From Production back with batch-managed items.

batches[].bins:
  Available bin quantities for that batch.
  Use this when the item is both batch-managed and bin-managed.

bins:
  Available bin quantities for item/warehouse when the item is not batch-managed.
  Use this when the item is bin-managed but not batch-managed.

If item has no batch and no bin, both batches and bins are empty arrays.

ProductionOrder componentType:
Item     = WOR1.ItemType = 4
Resource = WOR1.ItemType = 290

ProductionOrder status:
P = Planned
R = Released
L = Closed
C = Canceled

ActionType:
RELEASED = OWOR.Status changes to 'R'
CANCEL   = OWOR.Status changes to 'C'
Other Production Order changes are not queued.


ARReserveInvoice
----------------

objectType:
ARReserveInvoice

ObjectKey:
OINV.DocEntry where OINV.isIns = 'Y'

Current request body sent to /api/v1/b1/delivery:

{
  "params": {
    "deliverys": [
      {
        "siteId": "TEST",
        "docEntry": 47805,
        "docState": "release",
        "companyName": "TEST_STL_ODOO"
      }
    ]
  }
}

The field name "deliverys" is required by the current Odoo contract.

Delivery docState mapping:
ADD    -> release
CANCEL -> cancel

Outgoing companyName:
Uses SapDatabaseName, for example TEST_INTERFACE, TEST_STL_ODOO,
TIF_GOLIVE, or SBO_STL_GOLIVE.

Source tables:
Header = OINV where isIns = 'Y'
Lines  = INV1

ActionType:
ADD    = reserve invoice inserted
CANCEL = original reserve invoice CANCELED changes to 'Y'
Other reserve invoice updates are not queued.
