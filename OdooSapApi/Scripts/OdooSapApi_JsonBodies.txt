ตัวอย่าง JSON Body สำหรับ OdooSapApi
====================================

ข้อสำคัญ
--------
- ชื่อ field ด้านล่างเป็นตัวพิมพ์เล็ก/ใหญ่ที่ API ใช้จริง ให้ส่งตามนี้
- ชื่อ field ที่เป็นข้อมูลเดียวกับ ProductionOrder payload ฝั่ง OdooSyncWorker ใช้ชื่อเดียวกัน เช่น docEntry, docNum, lineNum, itemCode, warehouse
- ตอนส่ง request จริง ให้ส่งเฉพาะ JSON body ไม่ต้องใส่บรรทัดคำอธิบาย
- siteId ใช้เลือกฐานข้อมูล SAP จาก appsettings.json:
  TEST-TIF = TEST_INTERFACE
  TEST-STL = TEST_STL_ODOO
  PRD-TIF  = TIF_GOLIVE
  PRD-STL  = SBO_STL_GOLIVE


ข้อมูลที่ Odoo ไม่ต้องส่งมา
---------------------------
- sapDatabaseName: API จะหาให้เองจาก siteId
- docNum: request ไม่ต้องส่ง เพราะ API ใช้ docEntry หา Production Order และส่ง docNum กลับใน response ถ้าอ่านจาก SAP ได้
- processType: API กำหนดเองตอนเขียน log
- baseType: API ใส่เองจาก config ProductionOrderObjectType = 202
- baseEntry: API ใช้ docEntry ไปใส่ document.Lines.BaseEntry เอง
- sapDocumentEntry, sapDocumentNumber: API อ่านจาก SAP หลังทำรายการสำเร็จ
- status, errorMessage, requestJson, responseJson, processDate, processBy: API เขียนลง TEMP_API.dbo.INT_SapApiLog ให้อัตโนมัติ
- ข้อมูล connection SAP: อ่านจาก appsettings.json


การควบคุม SAP DI API
----------------------
- ไม่ต้องเพิ่มหรือเปลี่ยน field ใน payload
- API ใช้ config SapDiApi:MaxConcurrency = 2 เพื่อให้ DI API ทำงานพร้อมกันได้สูงสุด 2 request
- request ถัดไปจะรอคิวได้ SapDiApi:AcquireTimeoutSeconds = 20 วินาที ก่อนตอบ HTTP 503 และ header Retry-After = 15
- API ไม่ retry request อัตโนมัติ; Retry-After เป็นเพียงคำแนะนำให้ caller เท่านั้น
- HTTP 503 ข้างต้นเกิดก่อนเริ่มเชื่อมต่อ/สร้างเอกสาร SAP จึง retry request เดิมได้หลังเวลาที่กำหนด


รูปแบบ batch/bin ใน payload
==========================

- ชื่อ field เดิม batchNumber, batches และ bins ยังอยู่ เพื่อไม่ให้ payload contract เปลี่ยน
- Odoo ไม่ต้องส่งค่าใน field เหล่านี้; ถ้าส่งมา API จะไม่ใช้ค่าจาก caller
- Issue From Production และ Delivery: API เลือก Batch อัตโนมัติแบบ SAP Auto Select
- Receipt From Production: API สร้าง Batch ใหม่รูปแบบ yyyyMMdd-HHmmss จากเวลาท้องถิ่นของ API server
- API ไม่ส่ง BinAllocations ที่ caller ระบุ และให้ SAP ใช้ Auto Allocation / Default / System Bin ตามการตั้งค่าคลัง


1. Issue From Production
------------------------
POST /api/sap/production/issue

ข้อมูลที่ต้องส่ง
- siteId: TEST-TIF, TEST-STL, PRD-TIF หรือ PRD-STL
- docEntry: ค่าเดียวกับ ProductionOrder.data.docEntry จาก payload ที่ worker ส่งให้ Odoo
- docDate: วันที่เอกสาร/วันที่ posting ที่จะใส่เข้า SAP DocDate
- issueLines: ต้องมีอย่างน้อย 1 รายการ
- issueLines[].lineNum: ค่าเดียวกับ ProductionOrder.data.lines[].lineNum ใช้เป็น SAP BaseLine
- issueLines[].itemCode: ค่าเดียวกับ ProductionOrder.data.lines[].itemCode
- issueLines[].quantity: จำนวนที่ต้องการ issue จาก Odoo
- issueLines[].warehouse: ค่าเดียวกับ ProductionOrder.data.lines[].warehouse ใช้เป็น warehouse ที่ตัดของ

กฎเลือก Batch สำหรับ Issue From Production
- Item ที่จัดการด้วย Batch ทุกกลุ่ม รวม Item Group 109 และ 110 ใช้ Auto Select
- API ใช้ Batch ที่ผูกไว้กับ Production Order line ก่อน ถ้าไม่ครบจึงเลือก Batch Number จากน้อยไปมากจนเต็ม quantity
- ค่า batchNumber, batches[] และ bins[] ที่ caller ส่งมาจะถูกข้าม
- ถ้า warehouse จัดการด้วย bin: API ไม่กำหนด Bin เอง และให้ SAP ใช้กฎ Auto Allocation on Issue ของ warehouse
- ถ้า batch stock ไม่พอ API จะไม่สร้าง Issue From Production และตอบ error พร้อม itemCode, warehouse, required และ available
- issueLines[].itemCode ต้องตรงกับ item ของ Production Order line ตาม docEntry + lineNum

กฎสำหรับ Resource line
- API ตรวจจาก WOR1.ItemType = 290 โดยใช้ payload เดิม: lineNum, itemCode, quantity และ warehouse
- Resource line ไม่เข้า OITM, Item Group, Batch หรือ Bin selection
- ถ้าส่ง batchNumber, batches[] หรือ bins[] สำหรับ Resource line ค่าเหล่านี้จะถูกข้าม

Issue mapping เข้า SAP DI API
-----------------------------
- docDate -> document.DocDate
- docEntry -> document.Lines.BaseEntry
- issueLines[].lineNum -> document.Lines.BaseLine
- issueLines[].itemCode -> ใช้ตรวจสอบกับ Production Order line; ไม่กำหนด document.Lines.ItemCode เมื่ออ้าง BaseType/BaseEntry/BaseLine
- issueLines[].quantity -> document.Lines.Quantity
- issueLines[].warehouse -> document.Lines.WarehouseCode
- issueLines[].batchNumber / batches[] / bins[] -> คง field ไว้เพื่อ compatibility แต่ API ไม่ใช้ค่าที่ส่งมา
- Batch ที่ API เลือก -> document.Lines.BatchNumbers
- Bin -> SAP Auto Allocation on Issue; API ไม่กำหนด document.Lines.BinAllocations
- API ใส่ document.Lines.BaseType = 202 เอง
- Resource line (WOR1.ItemType = 290) ใช้ BaseType/BaseEntry/BaseLine/Quantity/Warehouse เหมือนเดิม แต่ไม่กำหนด Batch หรือ Bin


2. Receipt From Production
--------------------------
POST /api/sap/production/receipt

ข้อมูลที่ต้องส่ง
- siteId: TEST-TIF, TEST-STL, PRD-TIF หรือ PRD-STL
- docEntry: ค่าเดียวกับ ProductionOrder.data.docEntry จาก payload ที่ worker ส่งให้ Odoo
- docDate: วันที่เอกสาร/วันที่ posting ที่จะใส่เข้า SAP DocDate
- receiptLines: ต้องมีอย่างน้อย 1 รายการ
- receiptLines[].quantity: จำนวนที่ต้องการ receipt จาก Odoo
- receiptLines[].warehouse: ปกติใช้ค่าเดียวกับ ProductionOrder.data.warehouse เป็น warehouse ที่รับของเข้า
- receiptLines[].lineNum: optional; ไม่ต้องส่งสำหรับ Finished Good หลัก ส่งเฉพาะเมื่อต้องอ้างบรรทัดของ Production Order เช่น by-product โดยใช้ ProductionOrder.data.lines[].lineNum
- ห้ามส่ง receiptLines[].itemCode: เมื่ออ้าง Production Order ด้วย docEntry SAP จะหา ItemCode จาก BaseEntry/BaseLine เอง และไม่อนุญาตให้ DI API กำหนด ItemCode ซ้ำ
- ถ้า Item จัดการด้วย Batch API สร้าง Batch ใหม่เต็มจำนวนในรูปแบบ yyyyMMdd-HHmmss เช่น 20260907-212022
- ค่า batchNumber, batches[] และ bins[] ที่ caller ส่งมาจะถูกข้าม
- Bin ปลายทางใช้ Default/System Bin ตามการตั้งค่า SAP; API ไม่กำหนด BinAllocations เอง

Receipt mapping เข้า SAP DI API
-------------------------------
- docDate -> document.DocDate
- docEntry -> document.Lines.BaseEntry
- receiptLines[].lineNum -> document.Lines.BaseLine เฉพาะกรณีที่ส่งมา
- API ไม่กำหนด document.Lines.ItemCode; SAP ดึง ItemCode จาก Production Order ที่อ้างด้วย BaseEntry/BaseLine
- receiptLines[].quantity -> document.Lines.Quantity
- receiptLines[].warehouse -> document.Lines.WarehouseCode
- receiptLines[].batchNumber / batches[] / bins[] -> คง field ไว้เพื่อ compatibility แต่ API ไม่ใช้ค่าที่ส่งมา
- Batch ที่ API สร้างรูปแบบ yyyyMMdd-HHmmss -> document.Lines.BatchNumbers
- Bin -> SAP Default/System Bin; API ไม่กำหนด document.Lines.BinAllocations
- API ใส่ document.Lines.BaseType = 202 เอง


3. Close Production Order (TEMPORARILY DISABLED)
-------------------------------------------------
POST /api/sap/production/close

สถานะปัจจุบัน: route ถูกปิดและจะตอบ 404 จนกว่าจะเปิดใช้งานอีกครั้ง

JSON body
---------
{
  "siteId": "PRD-TIF",
  "docEntry": 49123
}

API ใส่ค่าเอง
-------------
- Production Order object type = ProductionOrderObjectType จาก config, default 202
- ClosedProductionOrderStatus = 2


ตัวอย่าง response กรณีสำเร็จ
============================

Issue From Production
---------------------
{
  "success": true,
  "message": "Issue From Production completed.",
  "data": {
    "siteId": "PRD-TIF",
    "sapDatabaseName": "TIF_GOLIVE",
    "documentEntry": "12345",
    "documentNumber": "60000123"
  }
}

Receipt From Production
-----------------------
{
  "success": true,
  "message": "Receipt From Production completed.",
  "data": {
    "siteId": "PRD-TIF",
    "sapDatabaseName": "TIF_GOLIVE",
    "documentEntry": "12346",
    "documentNumber": "59000123"
  }

============================
{
  "success": false,
  "message": "docDate is required.",
  "data": null
}
